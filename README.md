# D&D Character Art

Скилл для изображений персонажей D&D в рисовке приложенных референсов: выразительный тёмный контур, индивидуальные лица, штриховка, мягкие цветные тени. По умолчанию — погрудный портрет с подходящим герою ракурсом, всегда размытый фон, без надписей и посторонних предметов.

[Скачать последний релиз ZIP](https://github.com/Dezodemius/dnd-character-art/releases/latest/download/dnd-character-art.zip) · [Все версии](https://github.com/Dezodemius/dnd-character-art/releases) · [Сборки](https://github.com/Dezodemius/dnd-character-art/actions/workflows/package.yml)

## Использование в агентах

1. Скачайте ZIP из Releases и распакуйте папку `dnd-character-art`.
2. Поместите её в каталог скиллов вашего агента либо подключите `SKILL.md` как инструкции вместе с `assets/`. Путь установки зависит от агента; поддержка одного формата импорта всеми продуктами не предполагается.
3. Попросите применить `dnd-character-art` и опишите персонажа. У агента должен быть доступ к изображениям в `assets/` и инструменту генерации с визуальными референсами.

Необязательный `agents/openai.yaml` содержит только метаданные интерфейса Codex. Основные инструкции от него не зависят. Для Codex папку можно поместить в `~/.codex/skills/` (Windows: `%USERPROFILE%\.codex\skills\`); настройки конкретной установки могут задавать другой каталог.

Пример запроса:

> Примени dnd-character-art. Пожилая эльфийка-следопыт с короткими седыми волосами, шрамом на правой щеке и потёртым зелёным плащом. Взгляд в сторону, фон — осенний лес.

Можно задавать полный рост, другой кадр, ракурс, фон и собственный референс внешности. Собственный референс задаёт героя, сохранённые образцы — рисовку. Лес или другая выбранная локация остаётся размытой.

## Использование на сайтах с ИИ

1. Распакуйте ZIP. Откройте `SKILL.md`, скопируйте текст после блока YAML между первыми двумя строками `---` в поле инструкций или сообщение генератору.
2. Загрузите `assets/02-dwarf.png` и один-два подходящих стилевых образца из таблицы в `SKILL.md`. Если есть референс героя, приложите его отдельно и явно укажите его роль.
3. Добавьте описание персонажа. Если сайт имеет разные поля, поместите образцы рисовки в style reference, а изображение героя — в character/identity reference.

Если сайт не умеет импортировать ZIP, используйте распакованные файлы. Если он принимает только текст, агент сможет подготовить промпт, но точность рисовки без визуальных образцов будет ниже. Этот архив содержит инструкции и референсы, а не модель или расширение для сайта.

## Сборка и CD

GitHub Actions запускает проверку и упаковку на push в `main`, pull request и вручную через Run workflow. Готовый ZIP и `SHA256SUMS.txt` доступны как артефакт сборки в течение 30 дней. При push тега `vX.Y.Z` тот же workflow также публикует их в GitHub Releases; релизные файлы не зависят от срока хранения артефактов Actions.

Для нового релиза обновите `VERSION`, закоммитьте изменения, создайте совпадающий тег, например `v1.0.1`, и отправьте его на GitHub. При несовпадении версии и тега публикация завершится ошибкой. Повторный запуск для опубликованной версии проверяет идентичность файлов; при отличиях завершится ошибкой, сохранив существующий релиз. Повторная упаковка тех же файлов в одинаковой среде даёт тот же ZIP и SHA-256.

Локальная сборка из корня репозитория, Python 3.11+ без сторонних пакетов:

```console
python scripts/package.py
python -m unittest discover -s tests -v
```

Результат: `dist/dnd-character-art.zip` и `dist/SHA256SUMS.txt`. Пакет собирается по явному списку, не включает `.git`, настройки CI и локальные файлы. Сборка проверяет обязательные файлы, UTF-8, CRLF, структуру и содержимое ZIP. Workflow использует закреплённые ревизии официальных Actions и выдаёт права публикации только релизному заданию. Публикация использует штатный `GITHUB_TOKEN`, дополнительные секреты не нужны.
